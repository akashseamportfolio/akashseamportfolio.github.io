Storage & synchronization

Local mode

Last successful sync: Never

Application statuses, notes, overrides, manually added jobs and imported research synchronize in private app-specific Google Drive files. Research updates are separate from personal tracking. No access token is stored on disk.

Only the client ID is needed, never the client secret. Use the same Cloud project, client ID and Google account on every device.

First-time setup / reconnect instructions

First-time setup

  1. Open Google Cloud Personal mode setup. Sign in using the account where you want to store your tracking. Create a personal project, select Web application, and create the client. If Personal mode is unavailable, use Google Auth Platform, configure External audience and add yourself as a test user.
  2. In the same project, open Google Drive API and click Enable if needed.
  3. Open OAuth Clients and select your Web application client. Under Authorized JavaScript origins, add the exact origin below (no /jobstracker path). Save. No redirect URI is needed for this popup flow.
    https://akashseamportfolio.github.io
  4. Copy the Client ID (ending in .apps.googleusercontent.com), paste it into the field above, then click Connect Google Drive from the deployed tracker. Approve access to its own configuration data. Look for Synced to private Google Drive.

For an External test app, if required, use Data Access to add https://www.googleapis.com/auth/drive.appdata and Audience to manage test users.

Reconnect or use another device

Open the deployed tracker, go to Drive sync settings, reuse the original client ID if the field is blank, and click Connect Google Drive. Select the same Google account. If needed, click Sync now. To recover your original client ID, open the OAuth Clients link above and select the original project. Do not create a replacement project merely to reconnect; its app-specific data may be separate.

Troubleshooting

Origin mismatch: check the exact authorized origin and use the deployed HTTPS site. API disabled: enable Drive API in the correct project. Popup blocked: allow Google sign-in popups. Expired session: reconnect. Disconnect keeps local changes and does not delete Drive files. Export a backup before clearing browser data, revoking access or changing projects.

Daily research feed

Not linked. Your application sync works independently.

Linking creates or finds a private Google Doc named Personal Job Tracker - Daily Research Feed v2 in your Drive. The scheduled ChatGPT research task writes only to that document. The tracker reads the feed and merges research by job ID. It never reads or writes your application status, notes or overrides through that document.

Setup / reconnect help

Use your existing OAuth client ID and original Google account. Click Link daily research and allow access to the specific Drive files this application creates or opens (drive.file), in addition to its existing app-data access. No new client, API key, database or public sharing is needed. If Google requires a scope configuration, open Google Auth Platform Data Access in your original Cloud project and add https://www.googleapis.com/auth/drive.file. Keep the Drive API enabled. Then retry.

On another device use the same client and account, then click Link daily research to find the existing document. Reconnect when the access token expires. Do not rename or manually edit the machine-readable research document. If two matching documents exist, the tracker stops rather than guessing. Your personal progress is still stored separately.

Sync requires a registered HTTPS or localhost origin. The downloaded preview is for local tracking only. Keep exporting backups.
