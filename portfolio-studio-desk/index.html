A project page for the website you’re browsing

A home for my work, with a custom editor to help me look after it.

Design

I wanted one place for my games, films, artwork and other projects, with a clearer way to explain what I contributed to each of them. Here, you can follow a role on the homepage to a skill, then choose a project where I used it. Along the way, I wanted the website to feel personal and satisfying to use, while giving visitors control over its motion and navigation.

Technical

The portfolio runs on GitHub Pages, using HTML, CSS and JavaScript. I also added a custom browser-based editor, which I named Studio Desk, so I can change the content, arrange pages and publish updates from the same website. It uses the GitHub API to save private drafts and publish static files, with no separate application server for me to host.

My work

Product direction, experience design, information architecture, writing and iterative testing

Implementation

HTML, CSS and JavaScript · Browser-based editing · GitHub API · Static GitHub Pages publishing

Product definition

One home for the work, with evidence behind the titles

I make games, films, illustrations, animations and software, and I wanted them to feel like parts of the same practice. A list of links could show the finished pieces, but it left out what I contributed and how the work connects.

I also find it difficult to pitch myself. Imposter syndrome makes choosing a title uncomfortable, especially when my work crosses several disciplines. Connecting a title to something I have made gives me a concrete example to point to, rather than expecting someone to take the title at face value.

The idea is for each project to have its own home here. Every project now has an overview, while the longer case studies are still in progress. This page is the first of those, and the others will explain the decisions, contributions and lessons behind the work as I finish writing them.

Content design

An introduction you can follow into the work

I can click on any of the rotating roles on the homepage to go straight to the skill it refers to. From that skill’s row, I can choose a project dot to see where I used it. If that project has a published section about the skill, the dot takes me directly there. Otherwise, it opens the project overview.

The titles come from the roles I associate with skills in the editor. A role only appears when it has published project evidence behind it, so the introduction stays connected to the work instead of becoming a separate list of claims.

I gave skills with more linked projects more weight in the random selection. That lets the introduction reflect how much work I have documented in an area. It does not score my ability or suggest that a skill with fewer examples matters less.

Visitors can pause the rotation or use the arrows to explore at their own pace. I can also edit the titles and timing as the work develops.

Information architecture

Individual skills, connected to specific examples

I wanted the skills page to answer a practical question: where have I used this? Each skill has its own row, grouped into broader areas so the page is easier to browse without blending distinct skills together.

The dots are links to projects, not proficiency ratings. Hovering over a dot or focusing it with a keyboard reveals the project name, so visitors know where they are going before they open it.

I can connect a skill to an individual section of a case study. That means someone interested in a particular part of my work can reach the relevant explanation without having to read the whole page first.

The editor lets me add or remove project dots and change their destinations. A dot can point to an overview, a published section or an external project page while I am still preparing the material here.

Interaction design

Small interactions that feel deliberate and responsive

I wanted exploring the website to feel responsive and satisfying, including the small things people might never consciously notice.

The Work menu opens its projects in a panel beside the categories. Expanding a category used to push the categories below it around, which meant the next item could move away from the pointer. The side panel keeps those targets in place, with up to six projects and a link to the full category.

I used consistent hover, focus and pressed feedback across links and controls. The arrows, side panels and the small rotating square beside my name give an interaction a visible response without needing a large animation.

The portrait card is a small playful detail. Clicking or tapping flips it once, while dragging or swiping gives it momentum based on the gesture. I can interrupt a spin and turn it back the other way instead of having to wait for an animation to finish.

I wanted people to discover it without accidental movement competing with the introduction. The card stays still on hover, with a hint that appears on hover or keyboard focus. On touch screens, the hint appears briefly when the card comes into view and disappears when it is used.

Accessibility considerations

Give visitors control over motion and navigation

I wanted visitors to have control over movement. The roles can be paused or stepped through manually, the card does not spin on hover, and reduced-motion preferences simplify the animated interactions.

I added keyboard focus indicators, descriptive control labels and a skip link so the interface can be explored without relying on a mouse. Project dots also reveal their names on focus, rather than keeping that information behind hover alone.

The case-study sidebar links to individual sections. A floating back-to-top button and a subtle fade near the bottom of the viewport help with longer pages, and the fade disappears at the bottom of the page.

The layout adapts to desktop and mobile screens. Navigation, skill rows and project content rearrange to suit the available space, and the editor includes a mobile preview so I can check changes while working.

These choices are part of an ongoing process. I still need to keep checking contrast, assistive-technology use and the clarity of interactions as I add content, rather than treating accessibility as something finished.

Systems Design

A personal site builder, tailored to this portfolio

Once the site existed, I wanted to be able to keep working on it myself. I did not want every new paragraph, image or project to turn into another development task. That is why I added the custom editor introduced above, Studio Desk.

I think of it as a personal Squarespace of sorts, built around this portfolio’s structure. I can edit copy, upload media, add projects and arrange text, images, galleries, quotes and other supported blocks without editing the source files.

The live preview updates while I edit, with desktop and mobile views and a light/dark switch. That helps me see how a choice works on the page instead of imagining the result from a form.

I can change palettes, manage featured projects and connect skills to the sections where I explain them. The content relationships are editable alongside the writing, so the roles and project dots can develop with the portfolio.

I can publish a project overview while keeping its longer case study private until it is ready. Building new interaction behaviours still requires code, but routine content and layout changes are handled in the editor.

Technical specification

Static hosting, browser editing and controlled publishing

The public site is a collection of static HTML, CSS and JavaScript files on GitHub Pages. The editor runs in the browser too, so I do not have to maintain a separate application server for day-to-day editing.

The editor connects to the GitHub API to save draft content and write the public files when I publish. Draft storage and the published site are separate, which lets me prepare changes without immediately showing them to visitors.

The preview and publication use shared rendering code, helping keep what I see while editing aligned with what gets published. Sections marked unpublished, and media referenced only by those sections, are left out of the public export.

I can save backups and recover earlier versions. If another tab has saved a newer draft, the editor detects the conflict instead of silently replacing it, so I can decide which changes to keep.

My work on this project has been the product direction, experience design, content structure, writing and repeated testing. Implementation was AI-assisted, including development, debugging and revisions to the site and editor.
